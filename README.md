# devdocs-rag · 企业知识库问答

将产品手册、FAQ 和服务规范整理为可追溯的企业知识库，让客户用自然语言获得有来源的解答。

本项目属于「企业智能客服」开源学习路线：知识库问答 → 客服工具工作流 → 专项微调。首批知识资料采用 Dify Cloud 官方中文帮助文档，后续业务工具与工单使用独立的模拟数据。

> 状态：已准备首批知识资料，业务功能尚未实现。以下功能为目标范围。

## 使用场景

“如何邀请团队成员，邀请链接多久过期？” → 检索官方帮助文档 → 给出带原文出处的答案；资料不足或冲突时说明限制并澄清。

## 已准备的知识资料

[Dify Cloud 中文客服知识资料](data/knowledge/dify-cloud-zh/README.md)：15 篇官方文档，涵盖账号登录、团队权限、订阅账单、应用管理和知识库使用。

- `data/knowledge/dify-cloud-zh/documents/`：15 篇整理后的 Markdown，供阅读和后续 RAG 导入。
- `originals/`、`sources.json` 与许可文件保留原文、来源、提交版本和哈希。
- 第三方文档遵循 CC BY 4.0，与本项目代码的 MIT 许可分别说明。计费与配额属于固定版本快照。

## 首版计划

- 导入公开许可的产品帮助资料，保存来源、版本与下载日期。
- 完成文本切块、向量检索和基于证据的问答。
- 提供简单问答页面；知识未覆盖、冲突或失效时明确反馈。
- 固定至少 30 道客服咨询评测题，记录答案正确性、引用有效性和失败案例。

## 项目衔接

为项目二提供知识检索接口、咨询问题集与引用格式。产品知识随知识库更新，后续微调聚焦客服意图和工单字段。

- [devdocs-rag](https://github.com/dongyikuan919/devdocs-rag)：企业知识库问答。
- [issue-triage-agent](https://github.com/dongyikuan919/issue-triage-agent)：智能客服工作台。
- [issue-triage-lora](https://github.com/dongyikuan919/issue-triage-lora)：客服意图与工单微调。

## 开发路线

项目1 · 第 1～6 周；每周投入 8 小时：学习 2 小时、实现 4 小时、评测 1 小时、文档与提交 1 小时。

具体周计划与验收见 [阶段路线图](docs/ROADMAP.md)。采用 Python 主线，实际依赖和运行命令在首个可运行版本中补充。

## 当前范围

首版聚焦一个企业软件产品的公开样例知识库。接入真实企业资料前，必须由服务端限制知识访问和检索范围。

## 数据与配置

仅提交自写或许可允许公开的样例。API 密钥、真实客服会话、客户标识和未经授权的企业资料不入库；配置方案确定后提供 `.env.example`。真实业务数据接入须先落实身份、权限与隐私处理。
