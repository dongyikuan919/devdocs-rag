# 企业知识库问答：阶段路线图

当前状态：初始化完成，开发尚未开始。以下任务均为计划。

整体路线：企业知识库问答 → 智能客服工作台 → 客服意图与工单微调。三个项目分别交付，按验收推进。

| 周 | 要学什么 | 当周可检查的产出 |
| --- | --- | --- |
| 1 | Token、上下文、模型推理与训练的区别、HTTP/JSON、API 密钥管理 | 为一个虚构企业软件产品写清客服场景和 10 个典型咨询，跑通模型调用；记录耗时和用量 |
| 2 | Prompt、示例提示、结构化输出、基本 Transformer/Attention 概念 | 一个可重复运行的问答脚本，对固定输入比较两种提示；能解释模型为什么可能编造答案 |
| 3 | Embedding、相似度、切块与检索 | 导入 10～20 份产品手册、FAQ 和服务规范样例；保存来源与更新时间，输出检索段落 |
| 4 | RAG：先检索，再带证据生成 | 完成带引用的客服问答与简单页面；资料不足、冲突或已失效时说明限制并澄清 |
| 5 | 检索质量与回答质量的区别、错误分析 | 固定至少 30 道评测问题，比较直接问模型与 RAG，记录错误类型和改动前后结果 |
| 6 | 可复现安装、开源文档和发布 | 项目一 v0.1：从干净环境按 README 跑通示例，提交演示、评测报告和已知限制 |

## 阶段验收

- 示例场景是「如何开通团队账号」「某套餐包含哪些功能」「遇到问题如何联系支持」等产品与服务咨询。
- 首版知识来源限定为一个虚构企业的公开样例资料；接入真实资料前，知识访问与检索范围必须由服务端权限约束。
- 最少 30 题建议覆盖 15 题直接查找、5 题跨段落信息、5 题资料未覆盖、5 题版本冲突或容易混淆的内容。冲突与失效资料须说明限制，不能自行编造有效政策。
- 人工记录答案是否正确、引用是否真正支撑结论，以及检索是否找到预期段落。
- 示例验收目标：有资料的题目中至少 80% 回答正确且有有效引用；资料未覆盖的题目中至少 80% 明确说明不足。这是本项目自定目标，不是行业标准或结果承诺。
- 每题结果和样本数量一起公开，保留失败案例；小样本结果不代表泛化质量。

## 首版交付要求

- README 中说明实际可用的功能、运行步骤和限制。
- 提供可公开的虚构客服样例输入与输出，说明数据来源与隐私边界。
- 保留评测用例、结果和失败案例。
- 普通自动检查使用离线样例；在线模型评测单独运行，避免自动消耗 API 配额。
- 在干净环境中复核运行步骤后再发布 v0.1。
