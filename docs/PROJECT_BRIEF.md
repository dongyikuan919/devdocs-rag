# 企业知识库智能客服：项目目标与首版范围

## 项目目标

做出一个面向 Java 与 AI 应用开发岗位、可以公开演示和开源的实际项目。用户已确认以 Java 为主，兼顾 AI 和少量 Python。协作围绕功能交付、运行体验、问题修正与技术讲解展开。

主仓库为 [dongyikuan919/devdocs-rag](https://github.com/dongyikuan919/devdocs-rag)。原先的三个学习项目调整为一个项目的功能里程碑；后续客服工具也在主项目内推进，模型微调按实际需求再评估。

## 用户与场景

- 产品使用者希望通过自然语言找到产品帮助信息，并查看回答依据。
- 维护者希望能够导入资料、复现检索和回答过程，检查哪些问题回答正确或缺少依据。
- 首批演示使用已准备的 15 篇 Dify Cloud 官方中文帮助文档；资料与许可见 [数据索引](../data/knowledge/dify-cloud-zh/README.md)。

示例：用户问「如何邀请成员？邀请链接多久过期？」系统检索相关段落，生成答复并展示原文链接与资料版本。资料没有覆盖的问题应明确说明依据不足。

## 首版要交付的功能

1. 文档导入：读取 Markdown/TXT，保存来源、版本与文档标识；重复导入同一内容不生成重复知识。
2. 文档处理与检索：按标题和段落切块，生成 Embedding，并返回与问题相关的片段。
3. 知识问答：将检索证据交给模型生成答复，同时返回引用的片段与来源；未检索到依据时明确反馈。
4. 演示页面：输入问题，展示回答、引用和处理状态；配置与 API 凭据由服务端管理。
5. 评测与工程验证：保留固定问题集、关键用例测试、模型故障反馈和实际评测报告。

先以单个公开知识库的完整链路交付。文档正文属于不可信外部数据，不能授权执行工具或改变系统指令。后续接入非公开资料时，需要服务端权限控制。

## 技术路线

- 主应用：Java + Spring Boot。
- AI 集成：Spring AI，复用模型接入、Embedding 与 RAG 能力。
- 向量存储建议：PostgreSQL + pgvector，在一个数据库内保存检索向量与文档元信息。
- 页面：随 Java 应用启动的轻量问答界面，先满足完整演示。
- Python：后续数据处理或批量评测确有需要时使用，首版运行不以 Python 服务为前提。

本机已安装 JDK 17 和 Maven 3.9.6，但当前 shell 默认仍是 Java 8；构建时需明确使用项目所需的 JDK。Spring Boot 与 Spring AI 的具体版本在工程初始化时按官方兼容关系锁定。模型服务与 Chat/Embedding 凭据在接入时配置。

## 完成标准

- 能按 README 在干净环境启动，并导入已有的 15 篇资料。
- 能演示「导入 → 提问 → 检索 → 回答 → 查看出处」的完整链路。
- 在固定问题集上记录回答质量、引用支撑情况、缺少依据的反馈与耗时；效果指标用实际结果填写。
- 关键流程在 CI 中使用离线样例或模型替身验证；在线评测单独运行并记录模型、版本和用量。
- 发布代码、运行说明、演示、架构说明、评测结果和已知限制，保留第三方许可与署名。

## 可以在面试中解释的内容

围绕实际实现说明：为何选择当前切块方法、如何判断检索是否找对资料、如何让引用可核查、资料不足时如何处理、模型超时如何反馈，以及效果与成本如何衡量。每项结论都对应代码、测试或实验结果；项目经验按实际个人开源项目描述。
